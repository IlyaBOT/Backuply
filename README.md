# Backuply

Проект децентрализованной синхронизации папок между компьютерами, ноутбуками
и серверами с приоритетом локальной сети. Каждый узел хранит собственное
состояние и одновременно принимает и передаёт изменения. Центральный сервер
и доступ в интернет для работы в LAN не требуются.

**Статус: проектирование.** Исполняемый код пока представляет собой FastAPI-пример
с `GET / → {"message":"Hello World"}`. Синхронизация, обнаружение устройств,
передача блоков и SSH ещё не реализованы.

Подробный [анализ и выбор архитектуры](docs/architecture.md) сравнивает Syncthing,
собственный движок на Go и rsync, описывает транспорт, экономию трафика,
конфликты и хранение. [План разработки](docs/development.md) содержит этапы,
критерии готовности и программу измерения производительности.

Рекомендация: проверить требования на Syncthing как готовом движке и эталоне.
Для самостоятельного движка Backuply использовать Go, TCP + TLS 1.3,
передачу недостающих блоков и локальную SQLite. SSH — опциональный транспорт
с теми же правилами синхронизации. Это предложение, а не описание возможностей
текущего приложения.

## Запуск текущей заготовки

Нужны Docker Engine и Docker Compose с поддержкой `up --wait`.

```sh
docker compose up --build --wait --wait-timeout 60
curl --fail http://127.0.0.1:8000/
docker compose down
```

Порт HTTP доступен только на localhost. Проверка здоровья контейнера проверяет
ответ текущего приложения. Чтобы смотреть журнал: `docker compose logs -f prototype`.
Рабочие папки и SSH-ключи этому контейнеру пока не нужны.

## Проверки разработки

[GitHub Actions](.github/workflows/ci.yml) проверяет конфигурацию Compose,
собирает Docker-образ и ожидает успешной HTTP-проверки здоровья контейнера
на push, pull request и ручном запуске. После проверки контейнер удаляется.
Workflow начнёт работать после отправки файлов в GitHub при включённых Actions.
Публикация образов и развёртывание в этот workflow не входят.

Python-заготовка сохранена для непрерывности проекта. Переход на Go и тесты
нескольких синхронизирующих узлов описаны в плане, но ещё не выполнены.
Версии Python-зависимостей в исходном `requirements.txt` пока не зафиксированы;
это ограничивает воспроизводимость текущей сборки.
